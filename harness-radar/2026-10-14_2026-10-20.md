## 主题一：子代理、代码审查与评测

### 本期新内容

**1. [How the Claude Code team does code review](https://claude.dev/blog/solving-code-review-at-anthropic/)**

- 作者与渠道：Addy Osmani、Morgan Westlee Lunt、Qing Wang，claude.dev 博客，2026-10-15。身份证据：页面署名；Osmani 的个人网站自述为 Anthropic 技术团队成员、做 Claude Code；另两位页面未写职位，本期未单独核实。
- 陈述类型：以事实陈述和设计理由为主（自测数据），夹有 Boris Cherny 的个人判断（见下）。
- 说了什么：团队把大部分读代码的工作交给自动化，目标是“不增加回滚和事故的前提下，人工审查时间最少”。审查分层：提交前用全新上下文的子代理审 diff；每个 PR 上多个并行代理找 bug，另一组验证者（verifier）对每条发现投票，票数不够不发出，风格类、诊断类发现一律丢弃；安全审查可阻断合并；人工审批按风险分三档，档位由分类器按改动本身而不是作者来定，代理的批准不算人工批准，发起提示的人算必需审查者。
- 揭示的机制：(1) 验证者投票是“子代理用于验证”的具体做法，目的是压低误报；(2) `REVIEW.md` 把审查标准写在仓库里，由代码负责人维护，团队还单独检查审查器是否真的遵守；(3) 事故转评测（incident-to-eval）：把引发回滚的 PR 和修复收成评测集，每天给审查器打分，提示、工具、模型的改动只有分数提高才保留；(4) 收敛控制：代理对代理的审查会无限循环，一个 CLI PR 夜里跑了五十多轮，约 59% 被反复提出的是旧代码，所以加了三轮上限、只审 diff、按类别修、不重复发布。
- 自测数字（内部、无绝对基线）：合并的 PR 从 6 月到 9 月翻倍以上，被回滚的比例降了 40% 以上；一轮审查修复即通过的内部 PR 从 65% 升到 78%，需要五轮以上的从 8.9% 降到 1.5%。
- 观点与事实的区分：Cherny“验证让结果好两三倍”“验证大概最重要”是个人估计，不是测量结果。文中也承认还没有收紧审批的熔断机制，成本没有讨论。
- 和已知认知的关系：与 10-22 的“折叠子代理”文章互补——那里说“没有隔离或验证需求就别拆”，这里是需要独立验证时保留多代理的实例。
- 想深挖：自己仓库写一份 `REVIEW.md`，要求每条发现带文件行号和失败输入，再观察误报是否下降。

**2. Claude Code 更新日志 2.1.299–2.1.305（子代理相关）**

- 渠道：官方更新日志；陈述类型：事实陈述。日期：2.1.299/300 为 10-14，2.1.301 为 10-15，2.1.302 为 10-16，2.1.303 为 10-18，2.1.304 为 10-19，2.1.305 为 10-20。

- 揭示的机制：分叉子代理从“实验”变成默认，说明共享父上下文的子代理已被当作常规手段；并发上限和后台/前台划分说明编排层的资源控制已经是实际问题。

## 主题二：上下文管理与压缩

### 本期新内容

**Claude Code 更新日志 2.1.299–2.1.305（压缩与会话恢复相关）**

- 渠道：官方更新日志；陈述类型：事实陈述；各版本日期见主题一。
- 2.1.299：空闲压缩（idle compaction）——终端里超过 200K token 的对话空闲约 54 分钟后，在一小时的提示缓存过期之前先压缩；阈值可用 `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` 调，或在 settings.json 里关闭。
- 2.1.301：切换到上下文窗口更小的模型时，先由原模型把对话总结一遍。
- 2.1.304：压缩之后重新把技能列表给 Claude，`/reload-skills` 只发新增或变化的技能；与 2.1.300 一起修了多处无头模式、SDK 恢复会话时丢压缩摘要或最近消息的问题。
- 2.1.299 / 2.1.300 / 2.1.304 的其他相关条目：PDF 字节不再留在会话记录里；本地记录会保存每次请求的系统提示、工具和参数；长会话内存占用改善。
- 揭示的机制：(1) 压缩触发点与提示缓存的生存期挂钩：趁缓存还没过期先压，就不用在缓存失效后用全价重读整段上下文；(2) 压缩之后“常驻信息”（技能列表）需要显式再注入，说明摘要不会自动带着它们；(3) 换模型也是一个压缩触发条件。
- 想深挖：在一个超过 200K 的会话里空闲一小时后回来，看是否已压缩、技能列表是否还在。

## 主题三：权限、沙箱与 hooks

### 本期新内容

**Claude Code 更新日志 2.1.299–2.1.305（权限、沙箱、hooks 条目）**

- 渠道：官方更新日志；陈述类型：事实陈述。
- 沙箱与 auto mode：2.1.299 沙箱 shell 不再能写 `--plugin-dir`（插件在沙箱外运行）；2.1.302 新增 `CLAUDE_CODE_AUTO_MODE_MODEL` 选择客户端 auto mode 分类器用的模型；2.1.304 `rm -r` 在挂载盘上得到和 `rm -rf /Applications` 一样的安全提示；2.1.305 新增 `sandbox.allowNestedUserNamespaces`，文档自己警告这可能绕过沙箱的文件保护。
- 可观测性：2.1.301 OTel `tool_decision` 事件增加 `classifier_verdict` 和 `permission_mode`。
- hooks：2.1.299 插件 hook 无法收到请求或返回答案时，被阻止的动作按拒绝处理（失败即拒绝）；`UserPromptSubmit` hooks 现在先于技能或自定义命令展开；2.1.300 PreToolUse / PermissionRequest hooks 返回的 `updatedInput` 按 Claude 自己的输入同样校验；2.1.304 每个来源的技能最多注册 1,024 个 hooks。
- 揭示的机制：(1) 权限判断的分类器可以换模型并可观测，说明 auto mode 是一个独立的、可配置的组件；(2) hook 失败时倒向拒绝，方向与之后 2.1.309/2.1.310（本期之后）修复 Windows 上“失败即放行”一致；(3) 沙箱选项的文档直接写明代价，说明沙箱和权限规则是两层，彼此有缝隙。
- 想深挖：用 OTel 输出看 `classifier_verdict` 在一次真实会话中的分布。

## 主题四：工具、MCP 与 skills

### 本期新内容

**Claude Code 更新日志 2.1.299–2.1.305（工具、MCP、skills 条目）**

- 渠道：官方更新日志；陈述类型：事实陈述。
- MCP：2.1.299 云端和 Remote Control 连接器默认协商 MCP 协议版本 2026-07-28（`MCP_PROTOCOL_NEGOTIATION=legacy` 可退回）；允许规则只匹配字面上的服务器，`mcp__a` 不再覆盖名为 `a__b` 的服务器；2.1.300 工具的输入 schema 被 API 拒绝时，在本对话剩余部分不带参数发送，而不是每轮都报错；2.1.304 工具搜索在网关返回 400/422 时回退到无此功能的版本。
- skills：2.1.299 技能或命令名包含隐藏、改变方向或看起来空白的字符，或包含 `<` `>`，不再被提供，直到改名；技能的 `UserPromptSubmit` hook 从调用它的那条提示之后的下一条开始运行。
- 工具：2.1.301 Read 不再把 .xlsm、.parquet、.heic 当文本；Grep 和 Glob 在搜索程序失败时报错而不是报“没有匹配”；2.1.302 Read 拒绝超过 128 MB 的图片。
- 揭示的机制：(1) “工具失败不该伪装成空结果”——Grep/Glob 的改动直接避免模型把失败当成“没有”；(2) MCP 允许规则的精确匹配是权限边界修补；(3) 技能名过滤说明技能列表进了模型上下文，需要防止伪装。
