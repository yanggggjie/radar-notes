# Claude Harness 雷达 · 2026-10-20 至 2026-10-27

Oct 27, 2026 · @yangjie

## 本期概览

本周的主线是 Anthropic 在 10 月 22 日发布的 harness 设计指南：多数场景下，应把子代理（subagent）合并回单一 agent 循环，用技能（skills）和工具搜索（tool search）按需加载，只在能证明价值时才保留子代理。

最值得看的三条：

1. **官方指南《Building agents: When to fold subagents into your main agent loop》**（A 级，10-22）：讲清了“为什么单循环常常更好”背后的机制，也给出了子代理仍然适用的四种情形。
2. **Claude Duet 安全架构说明**（A 级，10-23）：把权限判断、出站消息检查和凭证保管全部放到工作模型之外，是理解 harness 安全设计的一份完整样本。
3. **Claude Code 2.1.304 至 2.1.310 的更新日志**（A 级，10-19 至 10-23）：集中修了压缩（compaction）、权限与沙箱、子代理和 hooks 的细节，能看出这些机制的实际边界在哪里。

**覆盖范围**：Claude Code 官方更新日志、Anthropic 官方文章与文档、Agent SDK 发布记录、Anthropic 发布说明聚合页、arXiv 预印本、科技媒体与中文社区文章。

**盲区**：X、Reddit、Hacker News 的帖子级讨论没能拿到可核实的日期和内容；知乎、公众号在 10-20 之后的原创分析搜索结果很少；GitHub issue 与 PR 级细节未覆盖；Claude Code 更新日志页面被截断，2.1.310（10-23）之后是否还有新版本未能确认。

**本期特点**：窗口内官方一手信息很充足，第三方原创分析很少，第三方文章大多是对 10-22 指南的转述。arXiv 论文里只有两篇（10-23 提交）落在窗口内，更早的几篇作为背景资料放在后面标明。

## 重点解读

### 1. 把子代理折回主循环：官方给出的默认做法变了

- **来源与可信度**：[Anthropic 官方文章](https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop)，作者 Diane Sarkis（Claude Platform），2026-10-22。**A 级**：官方一手发布。
- **发生了什么**：文章认为很多企业 agent 用“单一循环加按需加载的技能和工具”，在质量、成本、延迟上可以胜过多代理设计，子代理要在测量之后才保留。
- **揭示的机制**：
  - 共享上下文：单个上下文窗口里，前面步骤的结果可以直接被后面利用；多代理之间靠摘要交接，细节会丢，文章称之为“传话游戏”。
  - 渐进式披露（progressive disclosure）：技能和工具平时只放简短描述，用到时才完整加载。这去掉了“为了省提示词空间而拆子代理”的主要理由。Anthropic 称 Claude Code 对较强模型的系统提示词削减了 80% 以上，官方说其中一部分得益于这种做法。
  - 工具数量有软上限：系统提示里的工具定义超过约 30 到 50 个，选择质量会下降，所以要按用户意图分组，并用 tool search 延迟加载。
  - 子代理仍然合理的四种情形：单循环出现可测量的上下文膨胀；需要并行且每路用全新的一次性上下文；工具选择困难或指令互相冲突；需要验证、模块化权限或独立研究路径。
- **与已知认知的关系**：补充而不是推翻。子代理的价值（隔离上下文、并行）没有变，变的是默认值：从“先拆开”变成“先单循环，证明有必要再拆”。文章还说，较新的模型能在一个循环里自己规划和检查，部分 harness 逻辑因此变得多余。
- **要留意的限制**：“约 2 倍速”只来自一个未具名客户，没有披露比较条件；80% 针对的是初始指令文本，不等于总 token 或总成本；配套的 GitHub 迁移工具包据二手报道是不接受外部贡献的参考实现，且所有证据都来自 Anthropic 自己的部署。
- **想深挖**：读原文的迁移步骤（先建约 10 个样例的评测集，再逐个折叠子代理）；看 anthropics/single-agent-loop-kit 仓库；用 `/skill-doctor` 查看自己技能的成本与使用情况。

### 2. Claude Duet 的安全架构：检查全部放在模型之外

- **来源与可信度**：[Claude Duet Safety, Privacy, and Security](https://claude.com/resources/articles/claude-duet-safety-privacy-and-security)，claude.com 官方资源文章，2026-10-23。**A 级**：官方一手；其中“测试做得充分”这类说法是官方自述，没有外部验证。
- **发生了什么**：Duet 是 10-21 开启研究预览的云端后台 agent（美国 Pro 和 Max 用户，需排队）。这篇文章说明它怎样控制风险。
- **揭示的机制**：
  - 审批闸门：发送敏感消息、付款、删除等动作，会先展示动作、目的地和完整内容，等用户批准。
  - 独立的动作检查：每个动作旁边有一个由 Claude Code auto mode 分类器改编而来的检查，判断动作是否符合用户意图。它运行在干活的模型之外，所以网页里藏的指令影响不到它。
  - 出站消息分类器：另一个独立分类器在消息发出前检查敏感内容；被拦下时，agent 可以改写后再请求批准。
  - 凭证隔离：模型拿不到密码、cookie 和登录令牌。密码在应用里输入后以单次密钥加密；登录令牌则是 agent 的机器上只有占位符，由机器之外的代理在发请求时填入真实凭证，官方说这沿用了 Managed Agents 的设计。
  - 云浏览器：独立虚拟机，agent 只能用固定的命令集（打开页面、点击、输入）操作；页面文字和下载文件仍会回到 agent，所以注入风险没有消失，仍需其他防御。
- **与已知认知的关系**：印证并具体化了一条原则：安全检查不能由被攻击的那个模型来做。官方也承认分类器会漏判和误判，审批频率还在调整，属于未完成的设计。
- **想深挖**：对照 2026-03-25 的工程博客《How we built Claude Code auto mode》（见其他动态里的背景说明），看分类器是怎样判断“符合用户意图”的。

### 3. Claude Code 2.1.304 到 2.1.310：从修复清单读 harness 的实际边界

- **来源与可信度**：[Claude Code 官方更新日志](https://code.claude.com/docs/en/changelog)，2026-10-19 至 10-23。**A 级**：官方一手。下面按机制归类，归类是我做的。
- **压缩（compaction）不是一次摘要，而是有状态的流程**：
  - 2.1.305：压缩时如果不得不把最旧的消息排除在摘要之外，会告诉会话。
  - 2.1.304：压缩后会重新发送技能列表；转录视图（Ctrl+O）里的压缩摘要会列出之前调用过的工具。
  - 2.1.307、2.1.309、2.1.310：修复了工具结果很多时的“Autocompact is thrashing”、读到超大的嵌套 CLAUDE.md 后反复压缩（现在超限文件只加载开头）、遇到“Prompt is too long”后压缩保留过多密集文本（如 base64、SVG）导致下一次请求再次失败。
  - 读法：压缩要决定保留什么、丢什么、何时再触发，还要和技能列表、CLAUDE.md 加载互相配合，边界情况很多。
- **权限与沙箱要堵 shell 层面的旁路**：2.1.309 起，被排除在沙箱外的命令在沙箱无法运行时，写入沙箱白名单路径前会先询问，并拒绝无沙箱回退；`Edit(path)` 的拒绝规则现在也会拦住 Bash 的重定向写同一路径；Bash 权限检查不再信任可能因重定向失败而没设置的变量。
- **hooks 是安全边界，失败时不能放行**：2.1.309 和 2.1.310 修了 Windows 上缺少 Git Bash 时，PreToolUse 和 PermissionRequest hook 会“失败即放行”的问题；2.1.304 给每个来源（仓库、个人目录或插件）限制最多注册 1,024 个 hooks。
- **子代理**：2.1.307 起，同时启动的 fork 子代理会被告知哪一路是自己的，减少互相抢活；子代理转录开始记录真实的 token 用量和停止原因。
- **agent 循环与工具**：无法解析的工具调用最多重试两次，再以错误结束本轮（2.1.307）；HTTP 形式的 MCP 工具调用在连接中途断开时，只对只读或幂等的工具重试（2.1.307）。
- **想深挖**：同期的 [Agent SDK（TypeScript）发布记录](https://www.gradually.ai/en/changelogs/claude-agent-sdk/)里，v0.3.303 到 v0.3.310 多数是与 CLI 版本对齐的更新，可以对照看 SDK 与 CLI 共用同一套 harness 的程度。

### 4. 《Pairing Matters》：同一个模型，换 harness 最多差 44 个百分点

- **来源与可信度**：[arXiv:2610.32131](https://arxiv.org/abs/2610.32131)，Lu Zhao、Christopher M. Poskitt、David Lo，2026-10-23 提交。**B 级**：有完整实验数据，但是未经同行评审的预印本。
- **发生了什么**：研究者把 6 个开源 harness 和 3 个轻量开放权重模型两两组合，在 100 个 SWE-bench Verified 任务上跑出 1,800 次评分结果。
- **揭示的机制**：同一个模型，在不同 harness 下的解决率最多相差 44 个百分点；harness 的排名会随模型变化；在由模型主导循环的 harness 中，每解决一个任务所用的 token 相差 20 倍以上。
- **与已知认知的关系**：和 10-03 的预印本《What Does a Harness Buy? Tokens, Mostly》（背景资料）看起来矛盾：后者发现 Claude Code 与最轻的 mini-SWE-agent 得分差不到 5 分，只是成本差到 3 倍。两者的实验条件不同（强模型对轻量开放权重模型）。**这是我的推断，不是论文结论**：harness 对结果的影响，可能随模型能力下降而变大；这也和 Anthropic 指南里“较强模型让部分 harness 逻辑变多余”的说法方向一致。
- **限制**：不含 Claude Code，只覆盖轻量开放权重模型和 100 个任务。

## 原理线索汇总

本期把几条信息拼起来，最清晰的新认知是：\*\*减少常驻上下文，比事后压缩更根本；检查要放在模型之外；子代理是要付费的工具，不再是默认结构。\*\*下面按机制列出，每条标明依据来自哪几条信息。

- **上下文管理**
  - 官方指南的思路是让技能和工具只常驻简短描述、用到才加载（A 级）；更新日志显示压缩后会重发技能列表，超大的 CLAUDE.md 只加载开头，说明常驻内容和压缩是互相牵连的（A 级）。
  - 背景论文给出了同方向的数据：成本主要来自每一步重发的系统提示和工具定义（10-03，B 级）；上下文管理在窗口预算紧时价值更高，先规则裁剪再摘要最省（09-17，B 级）。
  - 小结：先让常驻部分变小，再谈怎样压缩。这是我对几条信息的归纳，不是单一来源的结论。
- **子代理与编排**
  - 官方默认值从“先拆分”变为“先单循环，证明有必要再拆”，保留理由有四种（A 级）。
  - 同一周，Managed Agents 文档仍把子代理（一层）、动态工作流和顾问列为可开关的三种机制（A 级）；Claude Code 则在让并行 fork 子代理知道各自的编号。两件事并存：子代理没有被淘汰，而是被当作有成本的选项。
- **工具与扩展**
  - 工具定义约 30 到 50 个以后选择质量下降，用 tool search 延迟加载；自定义 `ANTHROPIC_BASE_URL` 下 tool search 默认开启，网关拒绝时会去掉它重试（2.1.304 与 2.1.305，A 级）。
  - 每个来源的 hooks 数量有上限，说明扩展点本身也被当作需要限流的资源。
- **权限与安全**
  - Duet 把动作检查、出站消息检查和凭证保管都放在干活的模型之外（A 级）；更新日志里 hook 在 Windows 缺 Git Bash 时不再“失败即放行”，是同一原则在 Claude Code 里的体现（A 级）。
  - 背景论文指出，“用户批准允许规则”这个机制本身可被注入利用（10-16，B 级）。本周的权限修复与这个攻击面方向一致，但**没有证据**表明它们是对该论文的回应。
- **模型与 harness 的搭配**
  - 轻量开放权重模型下，同一模型换 harness 最多差 44 个百分点（B 级）；强模型下 Claude Code 与最简 harness 得分差不到 5 分（10-03，B 级）。
  - 这与官方“较强模型让部分 harness 逻辑多余”的说法一致，但这仍是推断，没有单篇论文直接证明。

## 待验证与存疑

本期最需要小心对待的是官方指南里的两个数字：它们都来自 Anthropic 自己的材料，原文没有披露足够的比较条件。

- **“单循环约快 2 倍”**：只来自一个未具名客户。可做的验证：用自己的一个多代理流程，先建约 10 个样例的评测集，再逐个折叠子代理，对照速度、成本和答案质量；多跑几次，因为官方示例里的失败只在两次运行中出现了一次。
- **“系统提示削减 80% 以上”**：只说明初始指令文本变短，不等于总 token 或成本下降，官方也没给基线。可做的验证：抓取同一任务在不同版本下的实际请求体，比较系统提示和工具定义占的比例。
- **掘金文章的“慢了 54%、花费翻倍”（D 级）**：页面没能打开，实验设置和数据都未核实，不应当作结论。
- **两篇论文看似矛盾**：“差不到 5 分”与“差 44 个百分点”的实验条件不同（强模型与轻量开放权重模型、不同 harness 集合）。“harness 的影响随模型能力下降而变大”是我的推断，没有论文直接验证。
- **权限升级攻击是否已被本周修复覆盖**：论文摘要没有说明测试的 Claude Code 具体版本，我也没有对照过更新日志逐条验证，所以不能说本周的权限修复已经堵住了它。
- **Claude Code 的版本范围**：更新日志页面被截断，2.1.310（10-23）之后是否还有新版本未能确认。
- **code review 文章的出处**：页面署名为 Anthropic 团队作者，但托管在 claude.dev，我没在 anthropic.com 工程博客列表里看到，建议自行确认域名归属后再当作官方材料引用。
