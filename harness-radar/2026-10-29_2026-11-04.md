**1. [Make long-running agents faster with message threads](https://claude.com/resources/articles/message-threads)，以及 [Message threads 文档](https://platform.claude.com/docs/en/build-with-claude/message-threads)**

- 作者与渠道：claude.com 资源文章（Announcements，无署名），2026-11-02；同日记入 [Claude Platform 发布说明](https://platform.claude.com/docs/en/release-notes/overview)。官方渠道、无个人署名，按“官方渠道发布”收录。
- 陈述类型：事实陈述（文档、发布说明）＋设计理由（文章说明为什么做）。
- 说了什么：
    - Messages API 新增服务端会话“线程”（thread），beta 头为 `message-threads-2026-08-12`。第一次请求带完整对话并加 `thread: {type: "create"}`；之后只发新消息，加 `{type: "continue", previous_message_id}`，并且**不再发 system 和 tools**，线程沿用创建时的值（[文档](https://platform.claude.com/docs/en/build-with-claude/message-threads)）。
    - 线程只在内存里加密保存、不落盘；最后一次请求后 5 分钟过期，最迟 1 小时删除。过期后要由客户端重放整段对话，所以**客户端始终是对话的唯一可信副本**（[文档](https://platform.claude.com/docs/en/build-with-claude/message-threads)）。
    - 模型每轮仍然读完整上下文，token 用量和价格不变，省下的是请求体积和首 token 延迟（TTFT）。官方给的数字：500K 到 1M token 的请求，TTFT 中位数下降约 35%；Claude Code 已对大多数用户默认开启（[文章](https://claude.com/resources/articles/message-threads)）。
    - 不能和这些功能一起用：按需压缩（compaction，`compact-2026-09-04`）、除 `clear_thinking` 保留全部之外的上下文编辑（context editing）、批处理、token 计数；每次请求最多 4 个 `cache_control` 断点；不支持 ZDR 和 HIPAA 组织（[文档](https://platform.claude.com/docs/en/build-with-claude/message-threads)）。
- 揭示的机制：agent 循环每一轮都要把全部历史（包括旧的工具结果、截图）重新上传，这是长会话的一项固定开销。prompt 缓存省的是**计算**，threads 省的是**传输**：缓存命中时服务端不重算前缀，但客户端仍要把前缀整个发过去；threads 把“前缀”留在服务端，客户端只发增量。文章明确说，上下文越大收益越大，所以长时间运行的编码 agent、带大量截图的 computer use agent 最受益。
- 和已知认知的关系：补充。此前对 harness 上下文管理的理解集中在“放什么进上下文”（压缩、上下文编辑、子代理隔离）；threads 处理的是“怎么把同样的上下文送过去”，是传输层的优化，不改变模型看到的内容。值得注意的是它与 API 层的按需压缩互斥：压缩要改写历史，而线程要求历史只追加不修改。
- 想深挖看什么：文档里 “How the SDK helper behaves” 一节（`client.beta.messages.thread()` 自动重放、`fork()`、`tool_runner()`）；小实验：同一段 500K 对话分别用普通请求和 thread 请求，记录请求体积与 TTFT。

**2. [Claude Code v2.1.314 / v2.1.317 的压缩相关条目](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)**

- 作者与渠道：anthropics/claude-code 官方仓库更新日志（同步于 [code.claude.com 更新日志](https://code.claude.com/docs/en/changelog)）；v2.1.314 标签时间 2026-10-30，v2.1.317 为 2026-11-03。发布标签由 GitHub Actions 打出，无个人署名。
- 陈述类型：事实陈述。
- 说了什么：
    - v2.1.314：“空闲压缩”（idle compaction）扩展到 VS Code 和桌面版 Code 标签页：超过 200K token 的会话闲置后先摘要好，若下一条消息到来时 prompt 缓存已过期，就直接用摘要；同时对关闭遥测的订阅用户，以及开了 1 小时缓存的 Bedrock、Vertex、Foundry 和网关也生效。终端里的空闲压缩更早已上线：闲置约 54 分钟、在 1 小时缓存过期前压缩（见更新日志较早条目）。
    - v2.1.314：PreCompact hook 的输出截断到 10,000 字符，因为过大的输出会让压缩失败或反复执行。
    - v2.1.317：修复了压缩不得不缩短自己的请求时，丢掉更早一次摘要的问题；修复了自动压缩后因为一个很大且被改过的 CLAUDE.md 报 “Prompt is too long”。
    - v2.1.317：**移除了 Read 工具的“文件自上次读取后未改变”占位**，再次读取未改变的文件会返回完整内容；同时 Grep、Glob 因超时被截断的结果不再被当作完整结果。对应地，[Agent SDK TypeScript v0.3.317](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md) 从 `FileReadOutput` 里删除了 `file_unchanged`。
- 揭示的机制：
    - 空闲压缩的触发条件是**缓存的生命周期**，而不是上下文是否接近上限：缓存一旦过期，下一条消息就要按全价重算整段前缀，不如在缓存还热的时候先压缩。这说明压缩决策同时在权衡上下文窗口和缓存经济性。
    - 压缩本身也会碰到“请求过长”，于是有“压缩缩短自己请求”的分支；摘要会层层累积，这次修的是累积链断裂。
    - 删除 Read 占位是一个反向取舍：占位能省 token，但模型可能在压缩后、或文件被外部修改的边界情况下拿到过期判断。Anthropic 选择多花 token 换正确性。发布说明没有写原因，这是推断。
- 和已知认知的关系：印证并补充上一期（[2026-10-26 至 2026-11-01](https://github.com/yanggggjie/radar-notes/blob/main/harness-radar/2026-10-26_2026-11-01.md) 一期记录的压缩后重新注入 CLAUDE.md、MEMORY.md）。压缩仍在快速迭代，边界情况集中在“摘要的摘要”和“注入文件的新鲜度”。
- 想深挖看什么：`/config` 里的 Idle compaction 开关、`CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`；小实验：在终端开一个 200K+ 的会话，闲置一小时前后对比 `/context`。

**3. [Lydia Hallie：压缩之后什么会被重新带回来](https://x.com/lydiahallie/status/2117306718917169483)**

- 作者与渠道：Lydia Hallie，X 个人帖（回复），2026-11-02 17:23 UTC（北京时间 11-03）。身份依据：本人 [X 简介](https://x.com/lydiahallie) 写明 “Claude Code @AnthropicAI @ClaudeDevs”。
- 陈述类型：事实陈述（描述机制，并指向文档）。
- 说了什么：Claude Code 压缩时会把对话里的一切（包括 skill 内容和读过的文件）都摘要掉，但摘要之后立即重新附上调用过的 skill，并重读最多 5 个最近修改的文件。她指向的 [文档 “What survives compaction” 一节](https://code.claude.com/docs/en/context-window#what-survives-compaction) 给了完整表格：系统提示照常生效；项目根目录 CLAUDE.md、自动记忆、plan 模式写的计划从磁盘重新注入；skill 描述按当前 skill 重建；调用过的 skill 正文重新注入，每个最多 5,000 token、总计 25,000 token，超出时先丢最旧的；带路径的规则和子目录 CLAUDE.md 按需重新加载；后台命令和后台子代理继续运行，并提醒模型避免重复启动；hook 早先加进来的上下文则与对话一起被摘要。
- 揭示的机制：压缩不是“摘要整段对话”这么简单，而是**摘要＋按来源重建**。凡是在磁盘上有权威副本的内容（CLAUDE.md、记忆、计划、文件）都不信任摘要，而是重新读取；只存在于对话里的内容（hook 注入、工具输出）才依赖摘要。这也解释了本期 v2.1.317 修的“大 CLAUDE.md 改动后压缩报超长”：重新注入的内容本身也会占预算。
- 和已知认知的关系：印证并细化上一期“压缩后哪些内容会被重新注入”的条目，这次有了带具体上限的官方表格。
- 想深挖看什么：上面的文档表格；小实验：调用 6 个 skill 后手动 `/compact`，看哪个 skill 的正文被丢掉。

## 主题三：权限、沙箱与 hooks

### 本期新内容

**1. [Claude Code v2.1.314–v2.1.317 与 Agent SDK 的权限、hook 条目](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)**

- 作者与渠道：官方仓库更新日志，以及 [Agent SDK TypeScript](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md)、[Agent SDK Python](https://github.com/anthropics/claude-agent-sdk-python/blob/main/CHANGELOG.md) 更新日志，2026-10-30 至 2026-11-03。
- 陈述类型：事实陈述。
- 说了什么：
    - v2.1.314 新增 `permissions.blockWritesOutsideWorkingDirectories`：在**任何权限模式**下，Write、Edit、NotebookEdit 都拒绝写工作目录以外的路径。SDK v0.3.316 新增 `permissions.blockReadsExemptPaths`：只能由宿主或 `--settings` 来源设置的一组路径，读限制放行它们，但它们不会因此变成工作目录。
    - v2.1.316：托管设置里的 `autoMode.allow` 不带 `"$defaults"` 时，不再把内置例外加回来，也就是用户列表会**替换**内置例外；桌面版 v4.16336.0 同步说明：`soft_deny`、`environment` 不带 `"$defaults"` 时则是**追加**到内置规则（[桌面更新日志](https://claude.com/docs/cowork/changelog)）。
    - v2.1.317：网页或 shell 调用会把账号邮箱发到网络上之前，Claude 会先询问；子代理的工具调用在 auto mode 检查给不出结论时会显示提示。
    - hook 失败时的默认行为可以改成“拦截”：Claude Code v2.1.317 让 Agent SDK 的 hook 回调支持 `onFailure: "block"`；Python SDK v0.2.177 对应加了 `HookMatcher(on_failure="block")`，回调抛错、返回 None 或返回无效输出时拦截，默认仍是 `continue`。
- 揭示的机制：
    - 写路径限制从“权限模式的一部分”抽出来，成为与模式无关的硬约束。权限模式（询问、自动、绕过）回答“要不要问人”，路径边界回答“能不能做”，两者被分开了。
    - auto mode 的规则是“内置默认 + 用户列表”的合并，`"$defaults"` 是显式的合并标记；allow 与 deny 的合并语义不同（替换与追加），这是一个容易踩坑的不对称。
    - hook 的失败语义原来是“失败即放行”（fail-open），现在可以按 hook 选择“失败即拦截”（fail-closed）。对把 hook 当作安全闸门的部署来说，这是关键开关。
- 和已知认知的关系：补充上一期的 auto mode 与失败处理条目。
- 想深挖看什么：[settings 文档](https://code.claude.com/docs/en/settings) 中 permissions 各键；小实验：写一个故意抛错的 PreToolUse 回调，对比 `on_failure` 两种取值。

**2. 桌面版的沙箱回退与技能扫描**

- 作者与渠道：[Claude Desktop / Cowork 更新日志](https://claude.com/docs/cowork/changelog)，v4.4212.0（2026-10-29）与 v4.16336.0（2026-11-03），官方渠道，无署名。
- 陈述类型：事实陈述。
- 说了什么：
    - 在 AppArmor 阻止沙箱启动的 Linux 主机上（例如通过 SSH 连接的 Ubuntu 24.04），失败的 shell 命令现在会**不经沙箱**再跑，出网白名单和文件夹限制对它们无效；在主机上给 bubblewrap 加 AppArmor 配置可以恢复沙箱。
    - 新增 `skillScanningEnabled`（beta）：用户创建或上传的每个 skill 在使用前要过安全扫描，不通过的被拦截。
    - Auto 和 Bypass 模式下，从 `launch.json` 启动开发服务器前改为先请求批准。
    - `desktopHome` 取代 Chat、Cowork 标签页开关，11 月 10 日起未设置时按 `standard`（开启 Cowork）处理；项目页发出的消息会启动 Cowork 任务，跑不了 Cowork 的电脑上则是普通对话。
- 揭示的机制：
    - 沙箱不可用时选择“回退为不受限执行”（fail-open）而不是“拒绝执行”，以可用性优先，并把恢复办法写进了更新日志。这与上一条 hook 的 fail-closed 开关正好形成对照：同一个产品里，不同的防线选择了不同的失败语义。
    - skill 被当作需要审查的“可执行内容”，有了上架前扫描。
- 和已知认知的关系：沙箱回退与 [Beyond permission prompts](https://www.anthropic.com/engineering/claude-code-sandboxing) 中“沙箱减少确认”的思路有张力：沙箱失效时，原本靠沙箱兜底的命令就失去了边界。是否同时恢复逐条确认，更新日志没有写。
- 想深挖看什么：桌面版的 [Unified Claude 文档](https://claude.com/docs/third-party/claude-desktop/unified-claude)；在 Ubuntu 24.04 上复现 AppArmor 阻止 bubblewrap 的情形。

## 待验证与存疑

- **threads 与压缩如何组合**：API 层的 message threads 不能和按需压缩一起用，而 Claude Code 既默认开启 threads 又会自动压缩。压缩后是否新开线程、空闲压缩是否等线程过期后才执行，官方没有说明。可以在 OpenTelemetry 导出里观察压缩前后的请求体积。
- **子代理 vs skill 的观点分歧**：Lydia Hallie 认为确定性的工作流（脚本编排的子代理）比 skill 更可预测；Addy Osmani 认为对自建 agent，单 agent 加 skills 往往胜过多子代理。两者讨论的场景不同（可重复任务 vs 一般 agent 设计），都是个人观点，不替你选边。
- **“系统提示删掉 80% 以上评测不降”**：只有 Addy Osmani 的个人长文作为出处，没有找到官方评测说明。
- **删除 Read 未改变占位的原因**：更新日志没有写，本笔记里“用 token 换正确性”是推断。
- **桌面版沙箱回退**：AppArmor 拦截沙箱时命令会不经沙箱执行，此时是否同时恢复逐条权限确认，更新日志没有写。
