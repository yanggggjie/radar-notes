## 主题一：上下文管理与压缩

### 本期新内容

**1. [Claude Code v2.1.311 压缩相关条目](https://github.com/anthropics/claude-code/releases/tag/v2.1.311)**

- 作者与渠道：anthropics/claude-code 官方仓库发布说明，发布账号 `ashwin-ant`（角色未核实），2026-10-26（年份推定）。
- 陈述类型：事实陈述。
- 说了什么：标准上下文（200K）的会话在请求超过 200K token 时，不再停在“需要 1M 上下文的额度”提示，而是先压缩再继续；自动压缩之后，此前在会话中被编辑过的 MEMORY.md、CLAUDE.md 不再以过期内容出现；模型回复里缺少摘要时，压缩流程通常会再请求一次摘要，之后才替换对话；`DISABLE_COMPACT` 设置后，agent 队友（teammates）不再压缩，回退菜单也不再提供“从此处总结”；设置文件与 mod 里的 `DISABLE_COMPACT` 只能关闭压缩，不能再把它打开；`/teleport` 载入已压缩的云端会话时会提示：本地副本缺少被摘要掉的消息。
- 揭示的机制：压缩由多个入口触发（超窗口、自动、手动回退），且包含“摘要缺失重试”这一步；记忆文件（MEMORY.md、CLAUDE.md）在压缩后需要重新读入，否则模型看到的是压缩前的缓存内容；已压缩的云端会话被 /teleport 载入时，本地副本缺少被摘要掉的消息，所以两端看到的历史不同。
- 和已知认知的关系：补充。此前的认知是“压缩 = 生成摘要替换历史”，这些修补说明实际流程还包括重试、记忆文件刷新和开关的单向约束。
- 想深挖：在一个会话里先编辑 CLAUDE.md，再触发自动压缩，对比压缩前后模型引用的内容；读 `~/.claude/projects/` 下转录里的 `compact_boundary` 记录。

**2. [Claude Code v2.1.312：子代理的 autoCompactWindow](https://github.com/anthropics/claude-code/releases/tag/v2.1.312)**

- 作者与渠道：同上，2026-10-27。陈述类型：事实陈述。
- 说了什么：子代理自己的 `autoCompactWindow` 现在可以把 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 设定的窗口调小，之前没有任何效果；仍然不能调大。
- 揭示的机制：自动压缩窗口有两层：全局环境变量给出上限，子代理的配置只能在上限以内收紧。这意味着不同子代理可以在不同的上下文占用点触发压缩。
- 想深挖：给一个子代理定义设置较小的 `autoCompactWindow`，看它在长任务中何时压缩。

## 主题五：人机判断分工与 agent 的呈现方式

### 本期新内容

**1. [How AI agents shape experts' judgment calls（Anthropic Research，Alignment 团队）](https://anthropic.com/research/agents-judgment-calls)**

- 作者与渠道：Amaç Herdağdelen、Hailey Joren、Alex Tamkin，Anthropic Research 页面，2026-10-27。身份证据：官方页面署名，页面标注 Anthropic Alignment 团队并感谢 Anthropic Fellows Program；个人所属单位页面没有逐人写明。完整论文为[页面链接的 PDF](https://www-cdn.anthropic.com/519c17a5d23a794e8b6d50a854048d0b61e0d73a.pdf)（本次只读了研究页面，未读 PDF）。
- 陈述类型：实验研究结果（证据），加上作者提出的设计建议（设计理由）。
- 说了什么：61 名有因果推断经验的专业分析师参加随机试验，11 人选择不使用 agent 而被排除出主分析，剩 50 人。他们在网页版 VS Code 环境里用 Claude Code（Claude Opus 4.8，High effort）完成一项任务：判断是否扩大一个虚构农业合作社的咨询项目。任务里留了 4 个各有两种合理选项的分析决定，一次抛硬币决定 agent 在每个决定上的倾向，agent 通过隐藏的系统提示被要求表达倾向、给出最强的诚实论证、证据明确时改变看法、不误导。结果：分析师的选择与 agent 倾向一致的比例是 86%（四个决定分别为 92%、82%、81%、90%），随机水平约 50%；对最终建议的影响较弱（agent 倾向推出时 54% 推荐推出，倾向另一方时 36%）；在 38 个分析师事先已有偏好的情形里，agent 不同意时他们有 60% 改变，agent 同意时 6% 改变（置信区间 24 到 82 个百分点，很宽）；77% 的分析师在解释里重复了 agent 的论点，只有 15% 说明来自 agent；52% 认为建议更像自己的。没有 agent 的 55 人中有 6 人出现严重错误，使用 agent 的 50 人中 3 人，但两组不可直接比较，作者提醒不做因果结论。
- 揭示的机制：在开放判断上，agent 的呈现方式（先表态、给出论证）会显著影响用户的选择；隐藏的系统提示可以决定 agent 的倾向。作者给出的 harness 层面的设计方向：让 agent 为每个选项给出最强论证、先问用户的看法再给自己的、只提出最关键的决定（但选择哪些决定本身也是判断）。另外，没有指定倾向时，Opus 4.8 在 123 次运行中有 112 次做出同样的五个选择。
- 和已知认知的关系：补充。此前 harness 讨论多关注权限与安全，这项研究关注的是 agent 的呈现方式对用户判断的影响。研究的局限：agent 的倾向是人为加强的，只涉及一个任务、一个领域、一个模型。
- 想深挖：读论文 PDF 里对 agent 回复的编码方式；在自己的 skill 或系统提示里加入“先问用户看法”的步骤，观察用户选择变化。

### 本主题小结

这项研究说明，harness 对话层的设计（agent 先说什么、说几种选项）会影响用户的判断，不只是模型本身的能力问题。它是实验结果，不是对 Claude Code 实际行为的说明。
