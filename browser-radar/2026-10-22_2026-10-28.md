## 主题一：演示录制、回放与工作流沉淀

本期最值得读的是 anomalyco/browse 的演示录制：它把“人演示一遍”压成五种结构化步骤，并明确要求回放前先补结果断言。

### 本期新内容

**anomalyco/browse：demonstrate() 录制人类演示**（新项目）

- 作者与渠道：anomalyco 组织，commit 署名 Ryan Vogel；GitHub。创建日 2026-10-27，来自 GitHub 搜索 API，我这次复核请求失败，未核实。创建当天已有 82 个 commit，更像是把已有历史推上来，不是一天写成。
- 证据等级：读过源码。`cli/src/demonstration.ts` 我亲自读了；`SKILL.md`、`session-journal.ts` 等是子代理读的，未复核。
- 解决什么问题：用户在自己的 tab 里做一遍任务，agent 拿到结构化步骤，而不是一段视频。
- 怎么做的：
  - 在每个 frame 的 document 上以捕获阶段监听 click、input、change 三类事件，监听器用 Patchright 的隔离（utility）world 注入，页面脚本看不到。主 frame 导航由 Node 侧的 framenavigated 记录，每次导航后重新安装监听。
  - 步骤只有五种：click、fill、check、select、navigation。连续对同一选择器的 fill 会被后一条替换，只保留最终值；相邻的相同 URL 导航会去重。
  - 选择器优先级：有 id 用 `#id`；否则依次试 data-testid、data-test、name、aria-label，且仅当在文档中唯一匹配才采用；再不行就生成 `tag:nth-of-type(n)` 的结构路径。
  - 密码框录成空值并标记 redacted，生成的代码里只留一条注释，说明应从已批准的密钥来源填充。
  - 输出是步骤数组加一段 Playwright 风格的草稿脚本，每步一行 `page.locator(...)`。
- 关键取舍：只监听三类事件，所以 hover、键盘快捷键、滚动都不会被录下；文件和按钮类 input 被忽略。选择器退化到位置路径时会很脆。非密码文本框的内容会原样录下来。
- 设计理由（来自子代理对 SKILL.md 的转述，未复核）：演示只显示动作，不显示成败，所以演示结果不会自动回放，agent 要先检查选择器、补上结果断言再复用。
- 对 yodo：这是“录演示、生成可复用步骤”最小的可读实现。选择器优先级和 fill 合并可以直接对照你的实现；“演示不等于成功，回放前补断言”可以当作泛化阶段的设计原则。
- 想深挖：`cli/src/demonstration.ts`，再看 `cli/skills/browse/SKILL.md`。
- 现状：10-27 当天仍有密集提交（子代理查到，未复核）。

**nitlix-studios/Vitamine：把成功的流程存成带参数的命名脚本**（新项目）

- 创建日 2026-10-23（搜索 API，未复核）；Apache-2.0，v0.1.0，只有 3 个 commit、2 star；commit 署名写明由 Claude Opus 5.5 生成。证据等级：子代理读过 `server/tools.ts`，我未复核。
- 做法：工具只有四个，tabs、run、scripts\_list、scripts\_save。run 执行一段异步 JS，全局有 page、tabs、net、cookies、logs、scripts。`scripts_save(name, description, code)` 把脚本存成 `scripts/<name>.js`，之后 `scripts.run(name, args)` 复用。
- 对 yodo：与“录制回放”不同，它让 agent 自己把跑通的流程固化成参数化脚本。这是比纯步骤回放更容易泛化的载体，值得拿来对比。
- 现状：窗口内最后一个 commit 在 10-23，之后没查到更新；仓库只有初始提交，成熟度很低。

**Eman0n911/deltadom：把每一步“agent 看到了什么”存成可校验的帧文件**（新项目，观察记录格式）

- 创建日 2026-10-22（搜索 API，未复核）；2 star。README 自己说项目目前在私有开发，0.4 是最后一个公开包，仓库内容可能滞后。证据等级：只读了 README。
- 做法：录成 .ddt 文件，首帧全量、之后每帧只存相对前一帧的增量，每帧带校验；回放不用重启浏览器，支持按步骤 diff，被中断的录制可以恢复到已校验的前缀。
- 数字（README 自述，未验证）：首帧 7,203 字节，不变的一步 76 字节。README 明说端到端成功率和成本的改善没有被证明；iframe 内部、closed shadow DOM、canvas 不抓。
- 对 TwoCursor：把“做一半的任务”交给 agent，需要一种紧凑的步骤间页面状态存储，“首帧全量、之后增量”值得参考。0.5 预览里的“点击前重新核对被绑定目标的身份，变了就停下”可以用在回放防误点上。

**loukan42/chaosfolk：回放不经过模型，且必须有断言**（新项目，QA 方向）

- 创建日 2026-10-26（搜索 API，未复核）；alpha，13 star。证据等级：只读了 README 和文件结构。
- 做法：agent 探索时注入故障，有希望的发现被写成带明确断言的场景，然后不经过模型回放。故障下失败 3 次、不加故障的对照跑 3 次都通过，才算复现；达不到的只保留为“观察”。退出码 1 表示产品失败，2 表示这次运行本身不可信。
- 对 yodo：回放验证可以借鉴“三种结果”：失败、对照通过、运行本身不可信，把“回放坏了”和“任务真的失败”分开。

## 主题二：人机交接与共享会话

本期交接设计的核心共识是：控制权的归还只认“页面外”的真实信号，人说完成了也不算验证。

### 本期新内容

**anomalyco/browse：handoff 状态机**（新项目，信息同上）

- 证据等级：读过源码。`cli/src/handoff.ts` 我亲自读了，下面的机制以它为准。
- 解决什么问题：脚本跑到登录、2FA、支付之前，需要暂停并把页面交给人，人做完后再安全地接回。
- 怎么做的：
  - 每个会话最多一个待处理交接。新的 wait 会先把同会话已有的交接以 timeout 结束。
  - 完成信号来自页内完成控件，工具栏按钮在有待处理交接时映射为 complete-handoff，这是页面脚本伪造不了的页外入口。完成时必须同时匹配交接 id、tabId、targetId、targetSessionId 四项，任一不符就返回 false。
  - 结果只有三类：resolved、timeout、cancelled（原因有 target-detached、target-crashed、session-stopped）。目标页面变化时可用 rebindTarget 重新绑定。
  - 有一个“持有期”中间状态：人在脚本动作进行中完成交接，会先记为 humanCompleted，等动作结束才结算为 resolved。
- 子代理对 README/SKILL.md 的转述（我未复核）：agent 只能操作自己开的 tab 或用户借给它的 tab；人说完成了之后，agent 必须自己断言已登录。
- 对 TwoCursor：单待处理项加四个 id 精确匹配，是一个现成的、小而严的交接协议；“只认真实点击”这一条值得照搬。
- 想深挖：`cli/src/handoff.ts`，以及 `relay.ts` 里 execute 与 handoff 的衔接（未读）。

**arcanemachine/pw-repl：人和 agent 共用一个 Playwright REPL**（HN Show HN，2026-10-26）

- 渠道与日期：Hacker News Show HN，发帖日 2026-10-26（Algolia 时间戳，来自子代理）。仓库页显示 470 个提交，看不到创建日，项目可能早于窗口，只是这一天才发帖，所以只能算“窗口内露面”。证据等级：读过 README。
- 做法：通过 CDP 附着到你用 `--remote-debugging-port` 和独立 user-data-dir 启动的 Chrome，或用 `--launch` 起私有无头 Chromium。多个客户端共用一个 REPL，各有自己选中的 tab。README 写明每条命令都会回显到 REPL，不论是谁发的，客户端命令显示为 `[server:<name>]`。serve 模式提供 Unix socket 和 127.0.0.1 上的 `POST /run`，客户端断开会取消命令。
- 与交接相关的模式：`watch` 记录用户在某个 tab 里的操作步骤及其引发的请求，`watch save` 能存成可重新运行的命令文件。
- 取舍：README 没有独立安全章节，也没写端口认证；CDP 端口等于完全控制浏览器。密码变量不出现在日志里，但对密码框执行 eval 不会被隐藏。
- 对 TwoCursor：这是“人和 agent 共用同一浏览器、命令按发送者归因”的最小实现，可对照你的“谁在操作”审计设计；它的 `watch` 正好是“人的操作变成 agent 可读记录”的一个原型，细节要看源码（我没读）。

**TheGitAI 浏览器控制：按 tab group 授权**（HN Show HN，2026-10-27）

- 证据等级：只读了产品文档，无源码，文档与实现是否一致未核实。
- 文档自述：扩展与本地终端程序通过本机通道交接内容，协议没写。每个会话独占一个 tab group，tab 需用户拉入，拖出即撤销权限；agent 只知道其他 tab 的数量，不知道标题和地址。默认模式用站点前要询问，plan 模式只读；下载默认暂停，登录和 CAPTCHA 交还给用户。
- 对 TwoCursor：“tab group 当权限边界”和“登录交还人”可以直接借来做交接设计，但要先去装扩展看 manifest 才能验证。

## 主题三：控制通道与登录态

本期的共同走向是“扩展加本地中继”：用真实已登录的浏览器换登录态，代价是权限很大，安全要靠额外护栏补。

### 本期新内容

**anomalyco/browse：扩展、本地中继与脚本执行**（新项目，信息同上）

- 证据等级：读过源码，但 `relay.ts` 和 `execute.ts` 没读；以下通道细节来自子代理，我未复核。
- 做法（子代理转述）：MCP server 走 stdio，连本地 relay（监听 127.0.0.1:19988，对外是 CDP 风格端点），relay 通过 WebSocket 连 Chromium 扩展，扩展用 chrome.debugger 执行命令。上层的 execute 工具在 Patchright 里运行 agent 写的 Playwright 代码，全局对象是 page、context、snapshot()、handoff()。也就是“agent 写脚本，一次调用多步”，不是一个动作一个工具。
- 会话模型：会话有名字，各有自己的 tab 组，重启后保留；空闲 10 分钟的 tab 自动关闭；每次 execute 往 journal.jsonl 追加一行，先脱敏（密码字段、JWT、Bearer、API key 前缀等），目录 0700、文件 0600。子代理读到的代码里日志只用于审计，没看到用它做恢复。
- 代价：扩展申请 debugger、tabs、scripting、tabCapture、webNavigation 以及所有站点权限，用户会看到“正在调试”横条。README 还默认开启拟人化输入（曲线鼠标、节奏打字）作为反检测手段，这与“人和 agent 共用”的语义可能冲突。

**nitlix-studios/Vitamine：通道有降级路径**（新项目，信息同上）

- 做法（子代理读过 `server/tools.ts`，我未复核）：Claude 走 HTTP MCP 连本地 Bun 服务（127.0.0.1:9333），再 WebSocket 到扩展，再用 chrome.debugger 控制 tab。CDP 被拒绝时（比如别的扩展已挂了调试器）自动退到 DOM 模式，用 chrome.userScripts 加合成事件，代价是丢掉网络和控制台捕获。
- 网络工具：net.list、get、replay、fetch，net.fetch 带页面 cookie 发请求；auth 头和 cookie 值默认隐藏，需 reveal:true 才显示。
- 取舍：agent 拥有任意 JS 执行和读 HttpOnly cookie 的能力，安全依赖 README 里的“请盯着它”和确认提示，没有硬隔离。
- 对 TwoCursor：`net.replay`/`net.fetch` 这种“抓到请求后以页面身份重放”的接口，与你“把请求记录成结构化数据”直接相关。

**hantiiii/agent-smith-browser：很小的工具面**（新项目）

**anomalyco/browse：snapshot.ts 的编号与压缩**（新项目，信息同上）

- 证据等级：子代理读过 `snapshot.ts`、`aria-snapshot.ts`，我未复核。
- 做法：每行形如 `- role "name" [ref=eN, ...]`，按缩进表示层级，只给可交互元素编号。编号在多次调用间持续，元素的（选择器、角色、名字）没变就沿用旧号。ref 到元素的映射存成 {selector, role, name}，选择器由 cssPath 生成，优先 id 和 test 属性，最后退到 nth-of-type 链；解析时先 `page.locator(selector)`，再用 getByRole 的精确名字收窄，页面或 URL 变了就直接报错。默认 compact 模式把大导航折叠，最多 80 项，按优先级裁剪后保持文档顺序。支持 diff 和 delta（有基线才 diff，否则返回完整快照）。

- 注意：评测对象是 WorkBench 里的 120 个数据分析任务，不是浏览器任务，模型是 Claude Haiku 4.5。我收它是因为“把一次成功运行编译成程序”和 yodo 的录制回放同构。证据等级：我核对了摘要页，没读方法部分。
- 做法：动作和数据变换变成代码，实例相关的值变成参数，需要判断的地方变成带类型的 LLM 调用。LLM 调用分输入、计算、输出三层，并用缓存、规则化、合并批处理三种手段减少调用。
- 页面上的数字：编译出的程序每次运行约 321 个输入 token、1.5 秒，带技能的 agent 约 23,138 个、4.4 秒，作者据此称输入 token 约少 70 倍、耗时约三分之一，不含编译成本。
- 对 yodo：“演示变代码，实例值变参数，只在需要判断的点保留 LLM”这个分层，可以用来决定回放时哪些步骤固定重放、哪些步骤交给 LLM。能否迁移到 DOM 操作，论文没有回答。

**其余三篇，只读了摘要（子代理读取，我未复核）**

- IGG：[arXiv 2610.32536](https://arxiv.org/abs/2610.32536)，2026-10-23，KAIST。601 个任务，考目标需要先滚动、悬停、拖动才出现的定位。摘要称瓶颈是“执行揭示交互”，不是认出目标。对 yodo：录制时要把“揭示步骤”也记下来。
- MiniWeb：[arXiv 2610.35823](https://arxiv.org/abs/2610.35823)，2026-10-26，犹他大学等。按 37 个交互原语、7 个技能族诊断 agent，称拖拽和手势最弱。对 yodo：演示拆步的粒度可以参考这套原语分类。
- AgentProofBench：[arXiv 2610.34634](https://arxiv.org/abs/2610.34634)，2026-10-25。研究“写给某个初始状态的完成验证器，在需求变化后是否仍然强制旧答案”。对 yodo：回放后判断“这次是否真的完成”，用前后状态差做验证，但要防验证器过期。

## 对 yodo 与 TwoCursor 的启发汇总

本期最可借鉴的是两个小而完整的机制：演示变结构化步骤（yodo），和只认页外信号的交接状态机（TwoCursor）。

**可直接借鉴**

- yodo：演示只录 click、fill、check、select、navigation 五类，连续 fill 合并成最终值，选择器按 id、测试属性、name、aria-label、结构路径的顺序退化（主题一，browse）。
- yodo：回放前必须补结果断言，把“回放坏了”和“任务真的失败”分开（主题一，browse、chaosfolk）；录制格式里同时存多种选择器作回退候选（主题一延伸，Chrome DevTools Recorder）。
- TwoCursor：交接完成要同时匹配交接 id、tabId、targetId、targetSessionId，只认页外的真实点击，人说完成了也要由 agent 自己断言（主题二，browse）。
- 两者：凭据用占位符注入、日志与录制里脱敏、不进模型上下文（主题二、五，Statelock、browse、1Password）。

**有冲突，需要权衡**

- 扩展还是 CDP：Chrome 136 起默认目录下调试端口被忽略，144 起要用户点允许。扩展路线能收窄 tab 范围，但要申请 debugger 权限并显示横条（主题三）。你的“记录请求”用 chrome.debugger 的 Network 和 Fetch 域，同一个 tab 上若已有别的调试器，就要有降级路径，Vitamine 的 DOM 模式降级是一个参照，我没读它的实现。
- 共享已登录浏览器本身就同时具备“不可信输入”和“敏感数据”两项，外发或改变状态的动作应当由人确认（主题五延伸，Rule of Two）。
- browse 默认开拟人化输入，目的是反检测；这与“人和 agent 明确共用”的语义可能冲突，要不要照搬要看你的场景（主题三）。
- Statelock 的后置断言检查的是动作之后的页面，动作已经发生，它防的是继续往下走，不是撤销这一下（主题五）。

**值得做的小实验**

- 把 yodo 已录制的几个流程，按 SkillShift 的三类漂移（改定位属性、改导航、加弹窗）人为扰动后回放，统计失败落在哪一类，先补最伤的那类。
- 给 TwoCursor 写一个最小交接状态机，加测试：伪造的完成信号、错的 tabId、重复交接都必须被拒。
- 把 pw-repl 的 `watch` 输出和你的结构化请求记录对比一下，看“人的操作变成 agent 可读上下文”哪些字段是必要的。
