## 端到端与回归测试机器人

本期唯一过关的是一个“测试没跑通就不让 Claude 收工”的 Claude Code 插件，它讲清了钩子怎么用，但我没能打开它的源码仓库，所以只算“读过详细作者文章”。

- **披露与现状**：[作者文章](https://dev.to/wst2002rk/your-ai-said-fixed-but-never-ran-the-tests-i-made-a-plugin-that-wont-let-it-say-done-until-5531)发于 10 月 27 日、10 月 28 日编辑；插件名 proof-of-done，文中称 MIT 许可、本地运行、无网络调用。
- **它做什么**：给 Claude Code 加一道“完成门”。Claude 想停下来时，插件检查最近一次代码编辑之后有没有跑过测试、结果是否通过，没有就拦住。
- **harness 怎么用的**：用的是 Claude Code 的钩子（hooks）。文章说钩子会记录每次代码编辑，以及每次测试、构建或 lint 的运行与退出码；Claude 要停下时检查记录并拦截。具体用了哪几个钩子事件、脚本怎么写，文章没展示，我也没打开源码，所以未核实。它通过 `/plugin marketplace add` 安装，文章给出的路径是 `WST2002/claude-code-skills` 里的 `plugins/proof-of-done`。
- **检查了什么**：识别 npm、pnpm、pytest、Go、Cargo、Maven 等项目命令；拒绝被 `| tail`、`| head`、`|| true` 吞掉退出码的运行，以及“零个测试被执行”的运行；同一检查在没有任何编辑的情况下先败后过时标为不稳定（flaky）；识别跳过测试、弱化断言、删除测试、调低覆盖率阈值这类篡改。
- **规模与成效**：没有任何基准数据。文中“58 个失败可能被 tail 吞掉”是作者的举例，不是测量；示例会话是作者自己的一次演示（[同一篇文章](https://dev.to/wst2002rk/your-ai-said-fixed-but-never-ran-the-tests-i-made-a-plugin-that-wont-let-it-say-done-until-5531)）。
- **业务真实性**：个人开发者的工具，真实使用规模未披露。作者自己承认，这道门的强度取决于项目里已有测试的强度，且对 monorepo 的处理文章没有说清。
- **能否复刻**：思路可以直接搬到你的 Agent SDK 服务里：在 Stop 钩子里查“最后一次编辑之后是否有通过的验证运行”，并且检查退出码有没有被管道吞掉。但请先自己读源码再用，文章没有给出钩子实现。
- **证据等级**：读过作者的详细文章（一手）；源码仓库未能打开。

## 被剔除与存疑

先说窗口内的一条：[Lessons Outlive Their Failures](https://arxiv.org/abs/2610.32578)（10 月 23 日提交）是单个人仓库上的六周实验，研究规则文件、技能、钩子对编码 agent 的影响，用的是三个未点名的工具，没有公开代码和数据，不是某个场景的实现，所以不收。Anthropic 工程博客列表里窗口内没有新文章，最新一篇是 10 月 13 日（[列表](https://www.anthropic.com/engineering)）。

下面这些实现质量不错，但首次公开日期不在本窗口（或页面看不到日期），按规则留给对应的期。这里记下我读到的要点，省得重搜：

- **客服·mufibra/customer-support-agent**（[仓库](https://github.com/mufibra/customer-support-agent)，页面不显示提交日期）：Claude Agent SDK（Python），`ClaudeSDKClient` 循环限 20 轮、预算 0.50 美元；4 个进程内 MCP 工具（查客户、查订单、退款、转人工）；PreToolUse 钩子强制前置检查、500 美元退款上限和每会话 3 次退款，PostToolUse 记审计日志；用的是假数据，`permission_mode` 是 `bypassPermissions`，项目尚无真实业务；37 个测试均为工具与钩子的单元测试。这是目前最接近你「后端客服服务」的代码骨架。
- **客服·luiscoco 课程示例 lesson53**（[仓库](https://github.com/luiscoco/Udemy-Claude-Agent-SDK-lesson53-app)，无提交日期）：TypeScript 版，`canUseTool` 把“发送回复”做成需浏览器审批的动作，批准仅对应一对工单与正文，两分钟过期；用 PostToolUse 钩子记审计。属于课程示例，数据是虚构的。
- **客服·一篇论文**（[arXiv 2610.14428](https://arxiv.org/abs/2610.14428)，10 月 10 日）：把客服排障流程生成做成“可移植技能”，论文自述 99.2% 与人工标准流程等价、证据充分率 83.3%，比生产助手慢约十倍（约 90 秒对 8 至 9 秒）；没有给代码，也没有说明用了哪个 harness。
- **E2E·TesterArmy e2e**（[博客](https://e2e.tester.army/blog/introducing-e2e)，10 月 1 日；[仓库](https://github.com/tester-army/e2e)，Apache-2.0）：用自然语言目标驱动浏览器和手机模拟器，通过了断言的 agent 步骤会记录并重放，不再调模型。但博客和 README 都没说它用 Claude Agent SDK，只提到 Claude Code 可以使用它的技能和 MCP，所以即使日期对上也不算 Claude harness 的实现。
- **E2E·Agentic Playwright**（[文章](https://note.com/totorotom/n/n497a2c8029fd?hl=en)，10 月 9 日，MIT）：用 Claude Code 的写前钩子（`.claude/scripts/enforce_constitution.py`）拦截 `waitForTimeout()`、XPath 选择器等 7 类违规写入，配 17 个技能和写后检查；钩子失败时放行（fail-open），不覆盖通过 shell 写文件的情况。这是与测试场景匹配度最高的一条。
- **E2E·voidmatcha/e2e-skills**（[仓库](https://github.com/voidmatcha/e2e-skills)，Apache-2.0，页面不显示日期）：4 个技能加 2 个专用 agent，用于生成、评审和调试 Playwright/Cypress 测试，附 24 类测试坏味道目录；README 称由评审结果产生了 15 个已合并的上游 PR（自述，未核实）。
- **E2E·OpenObserve 的 8 个 QA 子 agent**（[文章](https://openobserve.ai/blog/autonomous-qa-testing-ai-agents-claude-code/)，1 月 27 日）：每个 agent 是 `.claude/commands/` 里的一个斜杠命令，按分析、计划、写测试、审计、修复（最多重试 5 次）、记录的流水线接力；“测试从 380 增到 700+、不稳定测试从 30 多个降到 4 至 5 个”是作者六个月后的自述，文章没说明怎么量的，也没公开命令文件。
- **运维·Anthropic 官方 cookbook 的 SRE agent**（[页面](https://platform.claude.com/cookbook/claude-agent-sdk-03-the-site-reliability-agent)，2 月 16 日）：12 个 MCP 工具跑在独立子进程里，PreToolUse 钩子用 shell 脚本校验配置改动，工具处理器里写了目录、命令前缀、容器名白名单；跑在模拟环境里。
- **缺陷分诊·ChatPRD 的 Sentry 分诊 harness**（[文章](https://www.chatprd.ai/how-i-ai/how-i-built-a-custom-ai-harness)，7 月 8 日）：Agent SDK 加受限适配器，调查模式不能改代码，权限在代码里强制；没有公开仓库，成效只有一次演示运行。
